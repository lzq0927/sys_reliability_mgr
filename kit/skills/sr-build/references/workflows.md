# sr-build 工作流程

只加载当前任务相关小节。

### 开始
报告实际加载路径、版本和环境。检查任务 revision、输入文件与摘要、工作目录、可改范围、非目标及完成标准。读取未提交修改，保护已有工作；有并行写入风险时先协调或隔离，不能覆盖他人成果。

### 实现与调试
小步改动，沿用项目接口和规范。需求或指标冲突时保留证据并返回问题，不扩大产品范围。先复现再修复；不因旧报告预计通过而跳过本次验证。

### 实验与验证
运行与风险相称的实际测试，记录准确命令、退出状态、环境、代码版本、工作树状态、输入、种子或确定性配置。必要新增测试验证行为和边界，避免镜像实现。失败如实记录，未执行单独列出。

### 交接
回答原技术问题，解释关键实现与取舍；提供产物、证据、限制和结果包。测试通过不自动代表产业验收。复用 ReMAP 既有内网配置、依赖和发布方式；缺少实际仓库则不能声称已部署。
